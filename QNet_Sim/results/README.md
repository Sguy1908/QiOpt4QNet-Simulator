# `results/`: provenance and policy

Everything here is **generated output**, except `RESEARCH_FINDINGS.md`, which is
hand-written prose. Commands run from `QNet_Sim/`. The mapping below was derived
by reading which script writes each file; it was not checked by regenerating the
whole directory (the full suite takes hours), so if a file and its generator
disagree, the generator is authoritative.

`experiments/risk_gain_tradeoff.csv` used to have no generator.
`run_risk_gain_sweep` in `time_dependent_optimizer.py` now writes it; it
reproduces the archived served counts and utilities exactly, which confirms
the parameters. Its delivered-fidelity columns changed with the Werner
memory-decay fix (the old values, about 0.19, were below the physical floor
of 1/4) and are now 0.25 in every row: with `tau_mem = 5` the modelled hold
times fully decohere every pair, so that column carries no information in
this configuration. `hardware_profile_comparison.csv` was regenerated for the
same fix; it was also stale against the T1/T2 values in `hardware/profiles.py`.

`run_penalty_calibration_budget.py` writes `penalty_calibration/budget_sensitivity_runs.csv`
and `budget_sensitivity_summary.csv` (solver-budget sensitivity; see
`docs/PENALTY_CALIBRATION.md`). It is slow; `--workers N` splits the instances
across processes.

## Policy for committed binaries

The 46 committed PDFs and PNGs total about 3.5 MB, so this is a policy about
reviewability rather than repository size.

- PDFs and PNGs are committed so the manuscript in `paper/` builds without
  rerunning experiments: `manuscript.tex` takes the calibration figures from
  `results/penalty_calibration/figures/` (its other figures live in
  `paper/figures/`). They are marked `binary` in `.gitattributes`.
- Regenerate and commit a figure **only when the numbers behind it changed**,
  in the same commit as the data change, so a reviewer can see why a binary
  moved. Do not commit incidental re-renders.
- Compiled PDFs in `paper/` are rebuilt only when the `.tex` changes.
- Do not add other binary formats or large raw outputs.
- Git LFS or release assets are the next step if this outgrows the policy. That
  is a maintainer decision (it changes how clones fetch history), so it is not
  done here.
